# Database Schema Specifications — Product Guardian Network (PGN)

This document catalogs the PostgreSQL tables, constraints, keys, indexes, and schemas of the PGN application database.

---

## 1. Schema Definitions
All community and safety tables are organized under the namespace schema: `community`.

---

## 2. Table Directory

### 2.1 `community.community_users`
- Stores verified and unverified consumers submitting reports.
- **Fields**:
  - `id` UUID PK
  - `full_name` VARCHAR(255) Not Null
  - `email` VARCHAR(320) Unique Index, Not Null
  - `phone` VARCHAR(30) Nullable
  - `is_verified` BOOLEAN Default False
  - `created_at` / `updated_at` TIMESTAMPTZ

### 2.2 `community.product_reports`
- Stores product incident details reported by users.
- **Fields**:
  - `id` UUID PK
  - `user_id` UUID FK (references `community_users.id`, ondelete="CASCADE")
  - `barcode` VARCHAR(100) Index
  - `batch_number` VARCHAR(100) Not Null
  - `description` TEXT Not Null
  - `status` VARCHAR(50) (PENDING, APPROVED, REJECTED)
  - `created_at` / `updated_at` TIMESTAMPTZ

### 2.3 `community.report_images`
- Evidential media proofs (max 5 per report).
- **Fields**:
  - `id` UUID PK
  - `report_id` UUID FK (references `product_reports.id`, ondelete="CASCADE")
  - `image_url` TEXT Not Null
  - `uploaded_at` TIMESTAMPTZ

### 2.4 `community.report_credibility`
- Results generated by the CRCE engine.
- **Fields**:
  - `id` UUID PK
  - `report_id` UUID FK (references `product_reports.id` UNIQUE, ondelete="CASCADE")
  - `score` INTEGER Default 0 Index
  - `credibility_level` VARCHAR(20) Index
  - `calculated_at` TIMESTAMPTZ

### 2.5 `community.issue_clusters`
- Groupings of reports created by the PICE engine.
- **Fields**:
  - `id` UUID PK
  - `cluster_code` VARCHAR(50) Unique Index
  - `barcode` VARCHAR(100) Index
  - `batch_number` VARCHAR(100) Index
  - `primary_issue_type` VARCHAR(100)
  - `status` VARCHAR(50) (NEW, INVESTIGATING, RESOLVED, CLOSED)
  - `severity` VARCHAR(50) (LOW, MEDIUM, HIGH, CRITICAL)
  - `affected_reports_count` INTEGER
  - `affected_users_count` INTEGER
  - `affected_cities_count` INTEGER
  - `first_reported_at` / `last_reported_at` TIMESTAMPTZ

### 2.6 `community.cluster_intelligence`
- Analytics records produced by the CIE engine.
- **Fields**:
  - `id` UUID PK
  - `cluster_id` UUID FK (references `issue_clusters.id` UNIQUE, ondelete="CASCADE")
  - `risk_score` INTEGER Index
  - `growth_rate` FLOAT
  - `activity_level` VARCHAR(30) Index
  - `trend` VARCHAR(30) Index
  - `spread_level` VARCHAR(30) Index
  - `escalation_level` VARCHAR(30)
  - `average_credibility` FLOAT

### 2.7 `community.safety_alerts`
- Active community safety alerts.
- **Fields**:
  - `id` UUID PK
  - `alert_code` VARCHAR(50) Unique Index
  - `cluster_id` UUID FK (references `issue_clusters.id`, ondelete="CASCADE")
  - `alert_level` VARCHAR(50) Index
  - `status` VARCHAR(50) Index (ACTIVE, ACKNOWLEDGED, UNDER_INVESTIGATION, RESOLVED, CLOSED)
  - `title` VARCHAR(255)
  - `description` TEXT
  - `risk_score` INTEGER Index

### 2.8 `community.investigation_cases`
- Case files tracking safety alerts.
- **Fields**:
  - `id` UUID PK
  - `case_number` VARCHAR(50) Unique Index
  - `alert_id` UUID FK (references `safety_alerts.id`, ondelete="CASCADE")
  - `cluster_id` UUID FK (references `issue_clusters.id`, ondelete="CASCADE")
  - `assigned_officer` VARCHAR(100) Index
  - `priority` VARCHAR(50) Index (LOW, MEDIUM, HIGH, CRITICAL)
  - `status` VARCHAR(50) Index (OPEN, ASSIGNED, UNDER_INVESTIGATION, etc.)
  - `opened_at` / `closed_at` TIMESTAMPTZ

---

## 3. Indexing & Optimization Strategy
- Foreign key columns are indexed (`alert_id`, `cluster_id`, `report_id`) to optimize database joins.
- Filter fields (`alert_level`, `priority`, `status`, `created_at`) are indexed to speed up search endpoints and dashboard queries.
